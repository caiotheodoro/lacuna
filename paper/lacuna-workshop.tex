\title{Counting the actions no log recorded:\\a stress test of capture-recapture for agent trace completeness}
\author{Caio Theodoro}
\date{October 2026}

\begin{document}
\maketitle

\begin{abstract}
Audit regimes assume an agent's log is complete. When no single log is, the
actions missing from all of them are a population-size problem, and
capture-recapture over logs written by different infrastructure can estimate it. I
stress-test that on recorded episodes of a benign LLM agent in two environments
whose kernels keep a ledger no log reads, with log loss simulated afterwards. A
pre-registered back-office test passed all four hypotheses at its registered loss
seed (coverage 0.940, bar 0.90); over 30 fresh loss seeds coverage is 0.893. A
pre-registered infra test failed its coverage hypothesis (0.300, and 0.401 over 20
seeds), as registered. Both matched records by their effect; matching by ledger
id, which no auditor has, gives 0.948 and 0.946. Post hoc, linking two logs by an
id the harness writes into both recovers back-office coverage (0.946) but not
infra (0.859). Under exact matching, two loss patterns break the estimator: loss
concentrated on actions one log cannot see fails silently, and loss in bursts is
in back-office largely a case of the first. Nothing here tests an agent that hides
on purpose.
\end{abstract}

\section{Introduction}

Audit regimes that reach AI agents start from a log~\citep{euaiact}, and the
engineering around it answers whether a line was changed after it was
written~\citep{flightrecorder2026,vet2025}. Whether the record is whole is
assumed. Agents have been shown deleting their own trace events when asked, and
tampering unprompted when it raised their reward~\citep{qin2026tamper}; a line
never written leaves no trace in a hash chain.

The count of actions no log shows needs estimating only when no single record is
complete. A gateway that numbered every action before anything was dropped would
give it exactly. Where actions bypass the gateway, logs belong to parties that do
not share their numbering, or sampling comes first, epidemiology's method
applies: overlapping several incomplete registers estimates what all of them
missed~\citep{fienberg1972,bird2018mse}. I found no work applying it to agent
trace completeness; the nearest, over LLM judges counting label errors, produced
valid intervals too wide to beat a raw count~\citep{kansal2026labels}.

The contribution is a stress test on recorded episodes, not a deployed auditor.
In both environments here every action passes the gateway, so gateway numbering
would make the method unnecessary; the replays test the estimator, not a setting
that needs it. With loss that is independent by construction and exact matching,
the estimator is nominal, as it should be. The interest is in what breaks it:
\begin{itemize}
\item the record linkage an auditor can compute (\S\ref{sec:linkage});
\item loss that depends on which action it is, and loss in bursts
(\S\ref{sec:loss}).
\end{itemize}
This paper contributes a pre-registered test of capture-recapture for agent trace
completeness, a decomposition of its failures into record linkage and loss that
concentrates on what one log cannot see, and the post-hoc fixes that help.

\section{Setup}
\label{sec:setup}

An \emph{action} is a tool call that changes environment state or sends data
out. The environment kernel appends one ledger entry per action, so the true
count $N$ is a program, and no witness reads it. Three witnesses observe actions:
W1, the harness's trace of the agent's tool calls; W2, a gateway proxy log; W3,
an end-of-shift diff of the environment's state plus its outbound mail sink.

\paragraph{Estimator and assumption.} \texttt{ll\_bic} fits Poisson log-linear
models to the seven observed cells of the three-log capture
table~\citep{fienberg1972}, selects pairwise interactions by BIC and reports a
95\% profile-likelihood interval for $N$. It was chosen from a candidate set on
exploratory runs before either test. It assumes there is no three-way
interaction: the logs may depend on each other in pairs, but what all three miss
together is predicted by how they overlap. In the project's parametric simulator
of capture histories, a case where the agent's omissions are correlated across
all three logs leaves every point estimator at 0.218 coverage or less; only a
bound that takes an assumed limit on that correlation covers.

\paragraph{Linkage.} Matching records across logs \emph{exactly} uses the ledger
id, which no auditor has; some tables call it \emph{oracle}.
\emph{Effect-signature} matching pairs records on operation, resource and, for
some operations, value, in order within a signature.

\paragraph{Replays.} A live agent (\texttt{deepseek-v4.1-flash}, benign) worked
two environments: a back-office queue of refunds, cancellations, customer updates,
file writes and email, and an infra/ops queue whose end-state diff misses
transient work. Before any loss, the trace and the gateway each held every action,
so loss is simulated afterwards on the recorded episodes. Each \emph{replicate}
resamples the recorded episodes with replacement, drops log lines by the loss
model, and re-estimates $N$; \emph{coverage} is the share of replicates whose
interval contains the true $N$, and \emph{gap detection} the share whose lower end
exceeds the number of distinct actions any log saw. A $\pm$ is one Monte Carlo
standard error over loss draws. Because replicates reuse the same recorded
episodes, no error here covers what recording new episodes would change.
\emph{Post hoc} marks every result outside the two pre-registrations.

The env diff has two views in back-office. The \emph{registered} (financial) view
sees refunds, cancellations and sent mail but not customer updates or file
writes; the \emph{full} view sees every operation. In the held-out configuration
\texttt{fin\_mid}, each of the trace and the gateway loses half its lines at
random under the registered view. At the registered seed a replicate there hides
on average 63.15 of 828 actions from every log, and \texttt{ll\_bic}'s interval is
42.0 wide. The \emph{confirmatory pool} is the 21 registered back-office episodes,
with 30 tickets each. Two earlier back-office pools, \emph{long-60} and
\emph{long-120}, have 60 and 120 tickets per episode, with 10 and 5 episodes, run
on the previous model version (\texttt{deepseek-v4-flash}).

\section{The pre-registered tests}
\label{sec:prereg}

Each test was committed before its paid run (back-office \texttt{6ea27e2}, infra
\texttt{6774b24}), on loss configurations held out of the estimator choice, with
effect-signature matching as the headline. Each registered the same four
hypotheses:
\begin{itemize}
\item \textbf{H1/T1, coverage}: \texttt{ll\_bic} covers $N$ in at least 0.90 of
replicates;
\item \textbf{H2/T2, informativeness}: it detects the gap in more than 0.90;
\item \textbf{H3/T3, dependence}: when the trace and the gateway fail together,
\texttt{ll\_independence}, the model with no interactions, loses at least 10
points of coverage while \texttt{ll\_bic} loses under 5;
\item \textbf{H4/T4, floor}: \texttt{ll\_bic} beats counting the union of the logs
on gap detection by at least 0.50.
\end{itemize}
The back-office run deviated twice from its protocol: a crash forced a rerun on
the same seeds, and three episodes lost to provider errors were later restored on
a changed client (the ``restored, 24'' rows of Table~\ref{tab:precision}).

The back-office test passed all four at its registered seed, H1 at 0.940 over 100
replicates. The coverage pass did not hold up. Over 30 fresh loss seeds on the
same 21 episodes, signature-linkage coverage is $0.893 \pm 0.006$, close to the
bar given that error, and 0.862 with the three lost episodes restored, clearly
below it; with exact matching both pools are nominal (0.948, 0.945).

The infra registration was frozen after scripted infra runs had been seen, and
predicted that T1 would fail. It did: 0.300 at the registered seed, 0.401 over 20
seeds, against 0.946 with exact matching (Table~\ref{tab:transfer}). T2--T4
passed but say little: under signature matching the infra estimator claims a gap
even when nothing is hidden, so T2 and T4 could not fail, and T3 passes because
the interval doubles at the registered seed, from 55.82 to 108.34, around an
unchanged bias.

\section{What the registered linkage costs}
\label{sec:linkage}

In back-office, 0.223 of actions share an effect signature with another action in
the same episode; 179 of those 185 are emails to the same customer. In-order
pairing lines up records of different actions as one action seen by both the
trace and the gateway. BIC reads that as a trace--gateway dependence and selects
the model with that interaction alone in 0.358 of replicates, against 0.010 under
exact matching; the independence model, which cannot fit it, covers 0.948. In
infra, identical repeated actions collapse into one signature record, and
env-diff rows attach to the wrong record. The same mechanism produces false gaps:
when the two logs lose mutually exclusive actions, so that nothing is hidden, and
the env diff misses some actions, signature matching claims a gap in up to every
replicate (Table~\ref{tab:linkage}).

The signature left out content both the trace and the gateway carry: the harness
writes the provider's tool-call id into each. Linking those two logs by that id
alone restores 0.946 in back-office under the registered view, where the env diff
sees every email and is easy to attach, and removes every false gap measured:
with the trace and the gateway linked exactly, an overlap between them can no
longer be manufactured. With the full view it is 0.924, and in infra 0.859: the
env diff carries no id, and attaching its rows to identical repeated actions needs
a per-row id or timestamp. A variant that attached them by log order looked better
but produced false gaps of its own, and was withdrawn. A real gateway assigns its
own request ids, so this needs the harness, or the infrastructure, to stamp one id
on every log; an agent that writes its own trace could forge it, and that was not
tested.

\section{Loss the estimator does not expect}
\label{sec:loss}

\paragraph{Loss that depends on the action.} Raising both logs' drop rate on the
operations the registered view cannot see breaks \texttt{ll\_bic} silently. Under
exact matching it covers 0.647 at a tenth more loss and 0.187 at a fifth more
(0.657 and 0.197 under signature matching), on intervals barely wider than at baseline (40.8 and 43.4 against 38.9) that still
assert the gap (Table~\ref{tab:dose}). Past 1.2 times the loss, coverage rises
again, mostly because the interval grows to hundreds and then thousands of
actions. Under signature matching, stratifying, that is fitting each operation's
table separately and summing, stays near nominal where it answers up to 1.4 times the loss, and
refuses, giving no finite upper end, more often as the strata thin; this is its
best case, since the loss is keyed on the stratifying field.

\paragraph{Loss in bursts.} Dropping blocks of 12 consecutive actions per log,
each with probability one half and under exact matching, takes \texttt{ll\_bic}
to 0.559 in back-office and 0.802 in infra (Figure~\ref{fig:loss}b; 2000
replicates, \texttt{burst-loss.json}). Five disjoint sets of loss seeds
(\texttt{burst-loss}, \texttt{overdispersion}, \texttt{episode-dispersion},
\texttt{interval-comparison} and \texttt{final-controls}\texttt{.json}) put the same cells at 0.535 to
0.588 and 0.772 to 0.802; Table~\ref{tab:controls}, from the last, reads 0.588 and
0.772. In back-office this is largely the
first pattern again. The agent works one kind of ticket at a time, and the
actions the registered view cannot see are front-loaded: in the confirmatory pool
it sees 0.498 of the actions in the first quarter of an episode, against 0.745 to
0.804 later, and the long pools are more front-loaded still. A lost
block that lands early hides actions no witness then sees. Keeping the order but
permuting which actions the diff sees recovers 0.875 to 0.940. On the long pools,
the mean error is $+29.6$ and $+58.8$. In infra the bias is $+1.7$ and the
failure is mostly variance; shuffling the order of actions restores 0.912.

A quasi-likelihood correction~\citep{wedderburn1974quasi,mccullagh1989glm}, with
the dispersion estimated from how much the capture tables vary between episodes,
trades width for coverage (Table~\ref{tab:quasi}). Under per-record loss in
back-office it barely moves the interval; pooling both environments, whose
episodes differ, widens it about one and a half times. Applied to BIC's interval
only, it keeps the point estimate and covers 0.952 under bursts in back-office
and 0.994 in infra at about 2.5 to 3 times the width. Where the point is biased it
covers by widening: on the long-60 pool 0.894 at width 351.6, detecting the gap in
0.739 of replicates. Applied at model selection as well, it covers 0.934 at width
116.1 on the same draws, but under session quality shared by all three logs, the
case the no-three-way assumption excludes, it drops the interactions that were
absorbing that dependence and collapses to 0.009, where the plain interval covers
0.432. It does not flag loss concentrated by kind: at 1.2 times the loss in
back-office, the dispersion stays at its per-record value. Neither variant is a default; both were found after the
runs.

\section{What this does not show}
\label{sec:limits}

\begin{itemize}
\item \textbf{No adversary and no real log loss.} Every agent was benign and the
loss was simulated on complete logs. The main pools have 21 to 24 episodes, the
long pools 10 and 5, from two versions of one model family.
\item \textbf{A setting that needs the method was not tested.} Both gateways saw
every action, so numbering there would give $N$ exactly.
\item \textbf{Loss shared by all three logs} violates the no-three-way
assumption. Two variants in the technical report, a latent-class model and a fit
stratified by how many records each episode kept, reach 0.900 and 0.907 in one
environment each and 0.685 to 0.838 in the other; none is nominal. Outages that
take down all three logs at once leave no detectable gap.
\item \textbf{The author built the environments and set the bar.} The infra run
is scripted-equivalent and its verdict depends on a collision density the author
chose.
\item \textbf{The fixes are post hoc}, found on the same episodes that showed the
problems.
\item \textbf{Cheaper checks were not compared.} Seeded canary actions and
sequence-number gaps measure log loss directly and were not run head to head.
\end{itemize}

\section{Takeaways for an auditor}

In these replays the method gave a calibrated count only when three conditions
held. The logs were linked exactly, which a harness-written id achieved for two
of the three logs in one environment. Loss did not concentrate, by kind or by
time, on the actions one log cannot see. And no loss was shared by all three
logs. A dispersion-corrected interval beside the plain one flags loss
concentrated in time, at a cost in width and gap detection; it does not flag loss
concentrated by kind, which fails silently. When the first two conditions fail
the method can still say that actions are missing but not how many, and with
signature matching it can say so when nothing is. When all three logs fail
together it may not see the gap at all.
